# Playwright Automation Boilerplate

A team-ready automation project:

- `Playwright + TypeScript`
- multi-environment `env` support
- `fixtures / page objects / component objects / test data / e2e specs` structure
- lint, format, typecheck, and HTML/JUnit reporting
- a 5-skill Claude Code workflow for writing tests (`/plan → /write-test → /summarize-test →
  /review-test → /create-pr`) — see [CLAUDE.md](CLAUDE.md)

## Structure

```text
.
├── docs
│   ├── test-plan.md        # route → priority → suggested checklist (overview, not the final detail)
│   └── test-cases/          # per-feature test case summaries, generated by the /summarize-test skill
├── src
│   ├── config
│   └── utils
├── tests
│   ├── e2e                 # spec files, one subfolder per feature
│   ├── fixtures
│   ├── pages                # page objects, one file per screen
│   │   └── components       # component objects shared across pages (sidebar filter...)
│   └── test-data
├── playwright.config.ts
├── tsconfig.json
└── package.json
```

## Getting started

```bash
pnpm install
cp .env.example .env
pnpm exec playwright install
pnpm test
```

**Requires Node 20–22** (`scripts/run-playwright.mjs` auto-detects a matching Node version via nvm
if the default one isn't in that range; if no such version is available, the command fails with a
clear error instead of silently running on an incompatible version).

**About the browser:** `.env.example` sets `BROWSER_CHANNEL=chrome`, meaning Playwright uses the
Google Chrome installed on your machine (not Playwright's bundled Chromium). If Google Chrome isn't
installed, test commands will **hang** (not error out) while trying to launch the browser — either
install Google Chrome, or remove the `BROWSER_CHANNEL` line from `.env` to use the bundled Chromium
instead (already downloaded by `pnpm exec playwright install`).

## Main scripts

```bash
pnpm test
pnpm test:ui
pnpm test:headed
pnpm test:debug
pnpm test:smoke        # only runs tests tagged @smoke (--grep @smoke)
pnpm test:list
pnpm test:cross-browser
pnpm typecheck
pnpm lint
pnpm format
pnpm report
```

## Env strategy

- `.env`: local default
- `.env.stg`: staging
- `.env.prod`: production
- `CROSS_BROWSER=true`: enables Chromium + Firefox + WebKit
- `VIDEO_MODE`: `off` | `on` | `retain-on-failure` (default) | `on-first-retry` — set to `on` to keep
  a video for every test (pass or fail), e.g. as evidence for QA sign-off. Videos live under
  `test-results/`, and are linked from the HTML report (`pnpm report`).

Run per environment:

```bash
pnpm test:local
pnpm test:stg
pnpm test:prod
```

## Test-writing workflow

See [CLAUDE.md](CLAUDE.md) for details. Summary:

```
/plan   →   /write-test   →   /summarize-test   →   /review-test   →   /create-pr
```

1. `/plan` — reads the real `online-store-web` source (route, Vue Page component...) to produce an
   accurate checklist, not relying solely on `docs/test-plan.md`.
2. `/write-test` — implements Page Object / Component Object / spec from the approved checklist.
3. `/summarize-test` — summarizes the test cases just written into `docs/test-cases/<feature>.md`
   for easy verification.
4. `/review-test` — reviews against a Playwright-specific checklist (flakiness, locators, assertions).
5. `/create-pr` — runs the gate (`typecheck`, `lint`, `test:smoke`) then opens a PR.

## Extended conventions

- `tests/e2e`: spec files, subfolder names match the feature names in `docs/test-plan.md`
- `tests/pages`: page objects (one file per screen)
- `tests/pages/components`: component objects shared across pages — check this folder before
  writing a new page object to avoid duplicating logic
- `tests/fixtures`: shared test fixtures
- `tests/test-data`: static test data, don't hardcode repeated strings in specs
- `src/config`: config loading and validation
- `src/utils`: reusable helpers
- `docs/test-plan.md`: route → priority overview, not the final source of detail
- `docs/test-cases/`: per-feature test case summaries, for verification without reading code
